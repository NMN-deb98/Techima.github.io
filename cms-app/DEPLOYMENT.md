# استقرار آزمایشی پنل تکیما

## قبل از شروع
این برنامه روی GitHub Pages اجرا نمی‌شود؛ باید به‌عنوان یک Web Service در Render یا میزبانی مشابه مستقر شود. فایل `render.yaml` در ریشهٔ مخزن، سرویس وب و پایگاه دادهٔ PostgreSQL آزمایشی را تعریف می‌کند.

## استقرار در Render
1. ابتدا Pull Request شاخهٔ `cms-foundation` را بررسی کن و فقط پس از اجرای تست‌ها و تأیید تغییرات آن را ادغام کن.
2. در Render گزینهٔ **New → Blueprint** را انتخاب و مخزن `NMN-deb98/Techima.github.io` را متصل کن. اگر Render شاخه را می‌پرسد، `cms-foundation` را برای تست انتخاب کن.
3. Blueprint را بررسی کن. قبل از ایجاد سرویس مطمئن شو سرویس `techima-cms` و پایگاه داده تعریف‌شده‌اند. طرح رایگان پایگاه داده ممکن است محدودیت زمانی یا منابع داشته باشد؛ برای استفاده دائمی پلن مناسب انتخاب کن.
4. متغیرهای محیطی را در Render وارد کن:
   - `CMS_USERNAME`: نام کاربری مدیر دلخواه
   - `CMS_PASSWORD_HASH`: هش رمز، نه رمز خام
   - `GITHUB_TOKEN`: Fine-grained token که فقط به مخزن `NMN-deb98/Techima.github.io` دسترسی `Contents: Read and write` دارد
   - `FLASK_SECRET_KEY`: Render آن را از روی Blueprint تولید می‌کند؛ مقدارش را افشا نکن
5. برای تولید هش رمز، در یک محیط Python امن این دستور را اجرا کن و رمز را فقط در ورودی خصوصی وارد کن:

   `python -c "from getpass import getpass; from werkzeug.security import generate_password_hash; print(generate_password_hash(getpass()))"`

   مقدار خروجی را در `CMS_PASSWORD_HASH` بگذار. رمز خام یا توکن را در GitHub، چت، فایل `.env` commitشده یا فرانت‌اند قرار نده.
6. پس از Deploy، ابتدا `/health` را باز کن و بررسی کن که JSON با `status: ok` می‌آید. سپس `/login` را باز کن.
7. برای آزمایش انتشار، ابتدا یک پیش‌نویس بساز. انتشار عمومی را فقط پس از بررسی خروجی و مجوزهای GitHub انجام بده.

## محدودیت‌ها
این نسخه برای تست اولیه است، نه جایگزین کامل وردپرس. محدودیت نرخ ورود، MFA، مدیریت دیدگاه‌ها، آپلود رسانه، زمان‌بندی انتشار، تاریخچهٔ نسخه‌ها و فرایند حذف/لغو انتشار هنوز تکمیل نشده‌اند. پیش از استفادهٔ عمومی باید این موارد و تست امنیتی تکمیل شوند.
